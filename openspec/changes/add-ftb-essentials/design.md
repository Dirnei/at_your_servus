# Design

## Context

See proposal.md for the motivation. FTB Library, FTB Teams, FTB Chunks, FTB Quests and FTB Ultimine are already in the pack. The source of FTB Essentials 26.1.2.5 (FTBTeam/FTB-Essentials, `main`, 2026-10-05) shows:

- `teleportation.home.max` defaults to `1`.
- `/setwarp` and `/delwarp` require `CommandUtils.isGamemaster()`, which is op level 2. No config setting controls this.
- `teleportation.back` is on and not limited to deaths (`only_on_death = false`).
- `teleportation.rtp.enabled` defaults to `true`. The config's own comment says `/rtp` does not respect claimed chunks yet.
- All of these live in one startup config, registered as `ftbessentials-startup` through FTB Library's `ConfigManager`.

`config/waystones-common.toml` is shipped with Waystones' defaults. Its `[rules]` section has `enableXpCosts = true` (up to 27 XP points per trip, 27 across dimensions), `enableDurability = true` (a warp stone loses 80 durability per use) and `defaultVisibility = "ACTIVATION"` (each player must visit a waystone first). The config notes that `allowEveryoneToManageGlobalWaystones` is always on when `defaultVisibility` is `GLOBAL`.

## Goals / Non-Goals

**Goals:**
- Ship the mod with its defaults, except `/rtp`.
- Make Waystones free and shared with three config values, keeping the rest of the file unchanged.

**Non-Goals:**
- FTB Ranks or other per-player permissions. One home applies to everyone, ops included.
- Setting up actual warps. Ops place them on the live server; warps are world data, not pack files.
- Changing cooldowns, `/tpa`, or the other commands such as `/nick` and `/kit`, or the admin commands.

## Decisions

- **Ship only the startup config, generated by the mod.** Start the local server once with the mod, take the generated `ftbessentials-startup` file from `config/`, set `teleportation.rtp.enabled` to `false` and commit it. FTB Chunks' and FTB Ultimine's configs are shipped the same way. This keeps every key and comment the mod writes. A hand-written file could miss keys or use a wrong format. The comment in the source still mentions `defaultconfigs/ftbessentials-server.snbt`, but that is out of date: FTB Library 26.1.2 writes `.json5` files to `config/`. The file the mod writes is `config/ftbessentials.json5`.
- **Rely on built-in behaviour for one home and op-only warps.** Don't add redundant config lines for them. Only the `/rtp` change is a deviation, so only it goes into `docs/gates.md`.
- **Keep Waystones.** Warps are hubs that ops set up; Waystones stay as the players' own network. The alternative was to restrict `/home` further, but one home with a 10 s cooldown is already a light touch.
- **Free waystones through the global switches.** Set `enableXpCosts = false` and `enableDurability = false` instead of editing the Shogi `warpRequirements` rules. The switches are documented as the simple way to turn off all XP and durability costs, and they survive Waystones changing its default rules. `enableCooldowns` stays: the only cooldown is on the inventory button, which is off (`inventoryButton = ""`).
- **Shared waystones through `defaultVisibility = "GLOBAL"`.** Everyone can travel to every waystone, and everyone can manage global waystones (rename them, change their visibility). On a friends' server this is accepted. The alternative, `TEAM`, would split the network by FTB Teams, which goes against "available for everyone".

## Risks / Trade-offs

- [The startup config is read only at startup] → Restart the server after any config change (`docker compose restart mc`).
- [A future FTB Essentials update renames keys] → Check the file again when running `packwiz update`. FTB Library keeps unknown keys out and writes defaults, so `/rtp` would silently come back on. The manual `/rtp` check catches that.
- [The `/back` history (10 entries) lets players undo long trips] → This is accepted; it is QoL on purpose.
- [`defaultVisibility` affects only waystones placed or found after the change] → Waystones that already exist in a world keep their mode. A fresh server is fine; on an existing world, players or ops switch old waystones to global by hand.
- [Village and wild waystones may become global only when someone finds them, or already at generation] → Either way they are reachable by everyone. The manual check records which one happens.
- [Any player can rename or change a global waystone] → This is accepted for a friends' server. Revisit it with `TEAM` if griefing happens.
